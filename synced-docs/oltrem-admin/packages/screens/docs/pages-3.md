| `/access/roles/new?from=&name=`, `/access/roles/:id?view=` | three tabs at the top: Permissions (the default, the editor below), Assigned to (`?view=holders`, an existing role only: who holds it, the Rank and Remove; the page is titled with the role's name, and the tab is three cards, Assigned to (with Pick a user when none hold it) and, beside it, Rank and Remove; the page reads people, groups and grants only here) and Policy JSON (`?view=json`, open, no fold). The role editor: its name first; for a new role, Start from Nothing, a ready-made role (Viewer, Member, Admin: View, Edit or Manage in every module; renamed 2026-11-22) or Copy of any role but the Owner, as buttons of the same form so the name typed is kept (`from=template:see\|do\|manage`, `role:<id>`); then the permission matrix: one row per module, by the module's name (`names.ts`), sorted, each with how many of its permissions the role holds and its level as four chips always in view, None / View / Edit / Manage (each holds the one before; a level the module has not shows a dash in its place, faded chips before; a level holds what asks for a fresh sign-in or a second person's yes too, tagged beside it, and never the Owner's or the Vendor's own), no chip on and "Custom" when the ticks match none; the modules are one bordered list of rows (cards in two columns before); the arrow at a row's end opens its permissions to pick one by one, in words, each with its `area.thing.verb` name and Copy beside its box. Above the rows, on a row of their own, with the page script, Find a module (it hides the rows it does not match) and Set all shown to None / View / Edit / Manage (each shown row takes that level, or its highest below it). Under them, on the Owner role only, Special permissions: the Owner's own, grouped by module, to tick on purpose; Vendor-only never. A Save bar at the bottom holds the sentence of what it holds ("Views 6 modules, edits 3, manages 1"). The page script ticks a level's boxes and moves the level as boxes change; without it the server works the level out (below). The Owner role is the Vendor's to change: anyone else reads it as a summary with no Save. An existing role's Assigned to tab shows who holds it and Remove the role (a dialog first) only while it was never given; a role given, now or before, stays for the record and the page says so instead of offering a Remove the API refuses. A role but the Owner shows its Rank ("3 of 5, the Owner first") with Move up and Move down on Assigned to, and the Policy JSON tab shows: the role by its permissions' new names (the Owner role as `*`) with Copy, and a box to paste one and Import it in its place (a new role's page shows what it starts from and imports a new role, its Name needed) | `/api/iam/roles/:id`, `roles`, `capabilities`, `me`, `bindings?roleId=&inForce=true`, `groups`, `people` |

| `/access/groups/new`, `/access/groups/:id` | a new group's name; one group: its members, each with a quiet Take out (a dialog first); Add members, ticked from the users with an account who are not in it yet (never yourself), or by an address typed under "Someone not listed?"; the roles it holds as rows with Change and Remove; Give the group a role with the same role and place fields as inviting; Rename or remove the group, folded (Remove only for a group that never held a role, 2026-11-15).
