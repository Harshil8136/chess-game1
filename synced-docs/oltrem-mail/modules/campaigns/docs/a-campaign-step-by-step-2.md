# @oltrem/campaigns: A campaign, step by step: Sending, While it runs, Waits and stops, Unclear, Pause, resume, cancel, Run now, Run log, Fields in the message and more and more

> Part of [the @oltrem/campaigns README](../README.md).

## A campaign, step by step, continued

| Stage                 | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Sending               | The job `campaigns.send` runs every five minutes while any campaign is sending or waits for its start time; with none it asks one question of the database and sleeps (an hour a run), and a start, a resume or Send again wakes it. Each due campaign, the oldest first, gets the next people in the order of its list: no more than its pace, `campaigns.chunk_size`, a run's share of the Cloudflare plan (below), what is left of `campaigns.daily_limit` for the company that UTC day and its own daily cap. Before any call, the run writes on the campaign which people go under which call's key (the claim); the call is the email module's bulk pipe, one batch call of up to 100 for a provider that takes batches, one call a message for one that does not. Each person comes back sent, refused (failed, without counting towards the day), skipped (on the do-not-mail list a minute ago, a no-reply address, or at a domain the email module found with no mail server) or not sent (they go next run). One batch write records every person, the campaign's counters and the run's line for the page, and the run is audited as the system's `campaigns.run`. |
| While it runs         | People are added from a file or a saved list (who is on it already is kept once, who is never mailed is skipped) and people still waiting are taken off by address. The wording or template changes only while it is paused, as a new version; each person keeps the version they got. |
| Waits and stops       | It waits, says why on its page and goes on by itself: outside its sending hours; while its sender cannot carry bulk mail (warning alert); when the day is used up (until 00:05 UTC); when the provider's allowance is used up (until 00:05 UTC, warning alert); when the provider asks to slow down (for the wait it names, at least a minute). A refusal of the key, the account, the domain or the provider counts: three runs in a row and it pauses itself with a critical alert, until a person resumes it. |
| Unclear               | A call that got no answer (a timeout, a broken connection, a 500, 502 or 504) is sent again under the same key at the next run while the provider honours keys (Resend, for 24 hours; the run size halves after it and grows back). With a provider that honours none, or after 23 hours, the people of that call are unclear: nothing more goes to them until someone holding `campaigns.send` decides to send again, count them as sent or not send them. A run that died half way is settled by what the email module wrote for those keys before anything is sent again. |
| Pause, resume, cancel | A pause stops the chunks until it is resumed; a cancel ends it for good, and who was not sent to stays unsent.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Run now               | Someone holding `campaigns.run` makes a sending campaign's next run at once (since 2026-11-11 also one set to start later: it starts now, its start time moved to the moment of the press), as the five-minute run would make it: within the day's limit, its pace and hours, the plan's run and the provider's allowance (`POST /campaigns/:id/run`, audited as `campaigns.run-now`). A run holds its campaign for four minutes (`held_until`), so the five-minute run and Run now never run the same campaign at once: pressed while a run is under way, it says so and sends nothing. A campaign that waits (today's limit used, outside its hours) says why instead. |
| Run log               | The campaign keeps its newest 20 runs, waits and failures in words (`run_log`), newest first, with who pressed Run now: the page shows the latest eight inside the progress, refreshed every ten seconds while it sends. A run also keeps the provider's own answers for the people it did not send to (`answers`: failed, skipped or unclear, its words, how many, and the fix read from the words: a wrong address, the key, the sending domain, the provider's limit, the do-not-mail list, a file, or the download), the five most frequent shown under the run. |
| Fields in the message | The page lists each merge field the message or its template names, in whatever spelling it is written (`{{first_name}}`, `*|FNAME|*`, `{first_name}` and the others `@oltrem/email` reads), with the list's column that fills it: the same name, a well-known other name (`phone` from `Phone number`, `Celular` or `Mobile`; `first_name` from `Nombre`), or one picked from a row of the list's columns; and the words used when a person's value is empty. Saved with `POST /campaigns/:id/fields` (`field_map`, audited as `campaigns.fields`) on a draft, or a paused campaign by whoever may send it; the preview shows them filled in, and a field with a column or words no longer holds the start. This is the **Personalization** section: each field as a row with its state in words (From a column, Everyone has a value, N empty and the default used, **N would be blank**, Same text for everyone), **Value from** as one pick (a column, or **Same text for everyone**, `SAME_FOR_EVERYONE`, `-`: one text every person gets, the words in **Default value**) and a **Default value** box. While the campaign is a draft, `GET /campaigns/:id` counts once how many of its people would get each field blank (`empty`, one read of at most `FIELDS_CHECKED` people, `checked` saying how many were read), and **a field anyone would get blank stops the start** until it has a default (`a default value for {{x}} (N people have no value)`); a field written with its own words (`{{x\|there}}`) never does. |
| Tidying the list      | Since 2026-11-11, **Delete blank drafts** removes in one press every draft the person may write that has no subject, message, template, saved list, people or files (`POST /campaigns/remove-blank`, each audited as `campaigns.delete`); a sent or cancelled campaign is **archived** off the list, one at a time or all with **Archive finished** (`POST /campaigns/:id/archive`, `POST /campaigns/archive-finished`), shown under the **Archived** chip and taken back with **Take out of the archive** (`POST /campaigns/:id/unarchive`), audited as `campaigns.archive` and `campaigns.unarchive`. Nothing archived is deleted. |
| A run that fails      | A run that throws (the database busy, a bug) is caught for that campaign alone: the others still run, the reason is on its page and in the audit log (`campaigns.run-failed`) with a warning alert, and the next run tries again, settling from the claim it wrote. The third failure in a row pauses it with a critical alert, until a person resumes it. |
| The sender's name     | Every half hour, once 200 were sent, the run reads the reports on the campaign's latest messages (at most 1,000): above 0.3% spam reports (Gmail's limit) or 5% bounces for good it pauses itself before sending more, says which on its page and raises a critical alert (audited as `campaigns.protect`). A person looks at who complained or bounced, cleans the list and resumes it; the same reports are not read again for a day. The page shows the latest figures while it sends. |
| Sent                  | Once nobody waits, the campaign is marked sent and its figures are audited. The person who started it (the one who asked, when a second person approved) is emailed once, with the template `campaigns.summary`: the counts and a link to its page. |

Each message carries the key `campaigns:<campaign>:<person>`, where the email module's delivery
reports find it. With no email provider ready, or none that may send for the sender's domain, the
campaign waits and its page says why; it goes on once one is.
