# ai.md: read this first

**Every AI agent and every person starts here, in every session, before doing anything else.**
This file is the contract for this repository. Claude Code loads it through CLAUDE.md; Codex,
Cursor, Copilot, Gemini and the others reach it through AGENTS.md. Both pointer files are
generated by `pnpm agents:write`.

**The project.** Oltrem Mail is the email part of an Oltrem portal: the `@oltrem/email` and
`@oltrem/campaigns` modules (sending through the providers, senders and domains, templates, lists,
Write and Sent, bulk mail), and the `@oltrem/mail` add-on a client gets when Mail is ticked (the
Cloudflare route and its Mail setup page, and next an optional inbox).
It is packed into each client's repository next to the Oltrem kit (the private repository
oltrem-admin), runs on Cloudflare's free plan and always inside the portal's one Worker. The plan
is [docs/plan.md](docs/plan.md), approved by the owner on 2026-11-02.

## 1. Start of every session

1. Read this file to the end. Do not skim, and do not start the task first.
2. Acknowledge: begin your first reply with the words "ai.md loaded", then the twelve rules of
   section 2 and the four mail laws of section 3, one short line each, in your own words.
3. Check git: `git remote -v`, `git switch main`, `git pull origin main`, `git status`; in a fresh
   clone, `pnpm install`.
4. Read only what section 6 sends you to.

## 2. The rules, one line each

These are the kit's rules (oltrem-admin `rules.md` holds each in full, with its reason), applied
here. `pnpm check:agents` holds this file to one line for each.

- **R-01** Work on `main` and push to `main`; no pull requests unless the owner asks.
- **R-02** `pnpm verify` is green before every push; a gate is never skipped, weakened or bypassed.
- **R-03** Design, not code: nothing from the first client's repositories; open-source ideas are taken as designs and credited in the plan.
- **R-04** Everything here is written as if public: no account ids, keys, UUID shapes, live hostnames or personal data; examples use the reserved example domains.
- **R-05** A credential exists by name only, with a row in the token registry; reuse before create.
- **R-06** Generated files are never edited by hand; change the source and run `pnpm docs:build`.
- **R-07** Documentation changes in the same commit, in the one document that owns the fact; every document is indexed in docs/README.md.
- **R-08** ai.md stays the one entry file; CLAUDE.md and AGENTS.md only point here.
- **R-09** One of each resource per client and never a second Worker: mail adds tables to the client's one database and files to its one bucket.
- **R-10** Real data only, and fail closed: a route that cannot prove it is ready does not send.
- **R-11** Ask instead of guessing: a request with two readings, or a destructive step, stops for the owner's yes.
- **R-12** Phone first: every page is built for a phone; a page's options in a sideways row, its sections in the sidebar.

## 3. The mail laws

- **M-1** Never sent twice: a journal row exists before a message leaves, and an unclear answer is never retried by another route.
- **M-2** Cloudflare's sending carries transactional mail only, never campaigns or newsletters (Cloudflare's own rule).
- **M-3** Never past a limit: no send beyond a provider's known daily or monthly allowance, no KV writes for mail, 10 ms of CPU per request, cron run and received message.
- **M-4** Consent decides: the do-not-mail list and the person's choices are checked again just before each send.

## 5. How this repository and the kit fit together

The kit's packed packages this repository needs sit in `kit/`, recorded in `kit/kit.json`; the
overrides in package.json send each one there. After a kit change mail depends on: `pnpm kit:pack`
in oltrem-admin, `pnpm kit:refresh` here, `pnpm install`, `pnpm verify`. After a change here:
commit, `pnpm mail:pack`, then copy the folder into the kit's vendor/mail/ and run the kit's verify.
Every pack carries all of these documents in `published/`; the kit's docs mirror publishes them in
their own folder, `synced-docs/oltrem-mail/`, so a document is written as public from the start.
Package names, tables, routes and hook addresses never change in a move.
